What we built

The Pakistani Creative Collective platform is a Next.js app with a Postgres database (Supabase), styled to the brand spec (colors, fonts, logo, illustrations) with the full creative-profile and contact-request experience implemented.

Public site

  • Home page, member directory (free preview vs. full paid view), and individual creative profiles.
  • Free visitors see: name, role(s), experience level, location, bio, and one public link.
  • Paid subscribers additionally see: headshot, education, languages, mediums, social/portfolio links, primary work sample, and a "Work For Hire" card (rate info, travel, collaboration preferences).

Creative application flow

  • Public "Apply to Join" form (free) → admin review queue → approve/reject → applicant is emailed and gets a live profile.

Contact requests

  • Paid subscribers request an introduction via a form matching the spec: requester info, experience level, request type, message, timeline, and consent.
  • Submissions route to the admin panel; admin can forward to the creative or mark accepted/declined.

Subscriptions

  • $30/year early-access rate (pre-launch signups) vs. $50/year standard, enforced server-side.
  • Stripe Checkout + Billing Portal are wired up, but currently run in a safe demo mode (below) since live keys aren't set.

Admin panel & tests

  • Applications, contact requests, feature requests, and basic analytics (kept on a simple internal dark theme).
  • Vitest suite (npm test) covering signup/login, enrollment, contact requests, feature requests, admin moderation, and checkout — 30 tests, all passing.

Demo mode (no real charges or emails yet)

With STRIPE_SECRET_KEY and RESEND_API_KEY unset:

  • The subscribe page shows a "demo flow" banner and a "Simulate payment" button instead of real checkout. Clicking it marks the account paid (no money moves) and shows a success page noting the payment was simulated.
  • Application / approval / rejection / contact-request emails silently no-op — the in-app success screens still show, but no email is sent.

So the site is fully demoable end-to-end today without either vendor account.

What's needed before going live

Stripe — subscription billing

Used for: charging the $30/$50 annual subscription, the self-serve billing portal (update card, cancel), and keeping subscription status in sync via webhooks.
  1. Create a Stripe account and switch to live mode.
  2. Create two recurring Prices: $30/year ("early access") and $50/year ("standard").
  3. Set environment variables on the host:
    • STRIPE_SECRET_KEY — from the Stripe dashboard
    • STRIPE_PRICE_EARLY / STRIPE_PRICE_STANDARD — the two Price IDs
    • STRIPE_WEBHOOK_SECRET — from a webhook endpoint pointed at /api/webhooks/stripe, listening for customer.subscription.created/updated/deleted
  4. Once set, the demo banner disappears and real Checkout takes over — no code changes needed.

Resend — transactional email

Used for: notifying the team of new applications and contact requests, and notifying applicants/creatives of approval, rejection, and feature selection.
  1. Create a Resend account.
  2. Verify the sending domain (aneesatalks.com) by adding the DNS records Resend provides — required before it will deliver mail from noreply@aneesatalks.com.
  3. Set RESEND_API_KEY on the host. Every email flow then activates automatically.

Other required environment variables

  • DATABASE_URL — Supabase connection. Use the pooler connection (...pooler.supabase.com:5432), not the direct db.<ref>.supabase.co host (which is IPv6-only and won't resolve from many networks).
  • SESSION_SECRET — random 32+ character string for signing login sessions.
  • NEXT_PUBLIC_APP_URL — the deployed site URL (used in email links and Stripe redirects).

Note on the header font

The spec calls for Garet (bold, all-caps, tight letter-spacing). Garet is a licensed font not available on Google Fonts, so Plus Jakarta Sans (extrabold) is substituted as the closest open-license match. If you license Garet, swapping it in is a small change in src/app/layout.tsx.
